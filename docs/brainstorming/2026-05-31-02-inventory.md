# Panning Inventory: Open Brain Hardening Session (2026-05-31)

## Technical & Architectural Threads

1. **Protocol Integrity**
   - Idea: Strict adherence to the "Append-Only" protocol prevents data loss and maintains a truthful history of AI interactions.
   - Quote: "Core constraints: No simulating saves/retrievals, append-only storage, truthful reporting of connection status."
   - Category: Protocol

2. **Insight Preservation > Immediate Searchability**
   - Idea: In a knowledge base, losing the text of an insight is a critical failure; having a record that isn't search-ready for 10 minutes is a minor inconvenience.
   - Quote: "The text (the insight) is more valuable than immediate searchability."
   - Category: Architecture

3. **The Janitor Pattern (Embedding Backfill)**
   - Idea: A dedicated repair tool that scans for `embedding IS NULL` and processes them in batches, decoupling capture from embedding.
   - Quote: "Implementation of a 'Repair Tool' (The Janitor) to scan for `embedding IS NULL` records and backfill them in batches."
   - Category: Feature

4. **Explicit External Failure Reporting**
   - Idea: When external APIs (OpenRouter) fail due to credits/billing, the system should stop attempting retries and explicitly demand human owner intervention with the exact error.
   - Quote: "Must report exact errors from the embedding provider... and explicitly demand human owner intervention."
   - Category: UX/Error Handling

5. **Input Schema Rigidity**
   - Idea: Use mandatory Zod fields in `inputSchema` to force AI agents to provide all required parameters, reducing silent failures and tool crashes.
   - Quote: "Use mandatory Zod fields... to force the AI to provide necessary information before calling the tool."
   - Category: Reliability

6. **Binary Output Result Pattern**
   - Idea: Keep `outputSchema` optional so that a single tool can return either the requested data or a structured error/guidance block without schema violations.
   - Quote: "Keep `outputSchema` optional... allow the tool to return either the requested data OR an error message and guidance."
   - Category: Reliability

7. **Audit Roadmap Integration**
   - Idea: The v1 audit findings (parallelization, caching) should be treated as a prioritized backlog for the next set of implementation tasks.
   - Quote: "Integration of audit findings (parallelization via Promise.all, LRU caching) into the implementation roadmap."
   - Category: Project Management
